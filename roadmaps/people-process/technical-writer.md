# Technical Writer

## One-liner

The role that turns complex technical information into clear, usable documentation — the difference between a product users can figure out and one they can't; in 2026 also builds docs-as-code sites + AI-assisted docs.

## What It Is

A [Technical Writer](https://roadmap.sh/technical-writer) creates documentation: API references, tutorials, how-tos, architecture docs, runbooks, release notes. In 2026, technical writers also:

- **Write docs as code** — Markdown + Git + static site generator.
- **Use AI tools** — for first drafts, translation, grammar.
- **Build doc sites** — MkDocs, Docusaurus, Starlight, Mintlify.
- **Apply Diátaxis** — the dominant content framework (tutorial / how-to / reference / explanation).

The 2026 stack:

| Tool | Purpose |
|------|---------|
| **[Diátaxis](https://diataxis.fr/)** | Content framework (the standard). |
| **[Write the Docs](https://www.writethedocs.org/)** | Community + conferences. |
| **[Docs Like Code](https://www.docslikecode.com/)** | Docs-as-code philosophy. |
| **[MkDocs](https://mkdocs.org/)** | Python-based static site. |
| **[Docusaurus](https://docusaurus.io/)** | React-based; Meta's docs framework. |
| **[Starlight](https://starlight.astro.build/)** | Astro-based; modern docs framework. |
| **[Mintlify](https://mintlify.com/)** | AI-native docs platform. |
| **VS Code + Markdown + Git** | Standard editing. |
| **Vale / write-good** | Linters for prose. |

Adoption: Every developer-facing product has docs. Every enterprise has technical writers.

## When To Use It

- **You ship a developer product** — docs are essential.
- **You have complex APIs** — reference docs.
- **You want adoption** — docs drive activation.

## When NOT To Use It

- **Marketing-only content** — different role.
- **Tiny OSS project** — README is enough.

## Why It Matters in 2026

Three forces: (1) AI-assisted docs — LLMs draft + translate; (2) Docs-as-code is the default; (3) Good docs are a competitive advantage (Stripe, Twilio, Linear all win on docs).

Practitioner playbook: (1) Diátaxis framework; (2) Docs-as-code; (3) AI-assisted drafting + review; (4) Lint prose (Vale); (5) Version docs with code; (6) Measure doc effectiveness (search, feedback).
