# Developer Relations (DevRel)

## One-liner

The role that bridges a company and its developer community — builds trust through content, talks, demos, support, and open source; the engine of developer adoption for technical products.

## What It Is

[DevRel](https://roadmap.sh/devrel) (Developer Relations / Developer Advocate) is the function that helps developers succeed with a company's products. It combines:

| Sub-role | Focus |
|----------|-------|
| **Developer Advocate** | Public-facing evangelist; talks, content, demos. |
| **DevRel Engineer** | Builds DX tools; SDKs; sample apps. |
| **Technical Writer** | Documentation (see [technical-writer.md](technical-writer.md)). |
| **Community Manager** | Discord/Slack/forum moderation; events. |
| **Open Source Program Manager** | OSS strategy, governance, contributors. |

The 2026 DevRel toolkit:

- **Content**: blog posts, videos, podcasts, books.
- **Code**: SDKs, sample apps, starter templates.
- **Community**: Discord, GitHub Discussions, forums.
- **Events**: conferences (KubeCon, JSConf, etc.), meetups, workshops.
- **Open source**: maintain OSS, sponsor projects.
- **AI tools**: GPT-powered docs, AI search, code generation.

Adoption: Every developer-focused company has DevRel. CNCF projects have dedicated DevRel.

## When To Use It

- **You sell to developers** — DevRel.
- **You have an OSS project** — DevRel.
- **You want community-driven growth** — DevRel.

## When NOT To Use It

- **You're selling to non-developers** — sales / marketing.
- **No developer audience** — different function.

## Why It Matters in 2026

Three forces: (1) AI tools make developer content production easier (videos, docs, demos); (2) Developer audiences expect authentic DevRel — not corporate marketing; (3) OSS is the dominant growth channel.

Practitioner playbook: (1) Build in public; (2) Ship OSS; (3) Speak at conferences; (4) Write authentically; (5) Be helpful in communities; (6) Measure adoption, not impressions.

| Alternative | Better when | Worse when |
|-------------|-------------|------------|
| **Marketing** | Non-dev audiences. | Developer products. |
| **Sales engineering** | Enterprise deals. | Community + adoption. |
| **Support** | Customer success. | Acquisition. |
| **Open source maintainer** | OSS-first. | Commercial product. |
