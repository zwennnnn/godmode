# UX Design

## One-liner

The discipline of designing products that are useful, usable, desirable, and findable — grounded in research, tested with users, and refined iteratively.

## What It Is

UX (User Experience) design is the practice of designing the entire experience a person has with a product — not just the visual interface, but the workflow, the information architecture, the emotional journey, and the outcomes. UX design combines:

| Discipline | Focus |
|------------|-------|
| **User research** | Understanding users through interviews, observation, surveys, analytics. |
| **Information architecture** | Organizing content and functionality for findability. |
| **Interaction design** | Defining how users interact with elements; flows, states, transitions. |
| **Usability** | Ease of learning, efficiency, error prevention, satisfaction. |
| **Visual design** | Layout, typography, color, hierarchy. |
| **Accessibility** | Inclusive design for users with disabilities (see [accessibility.md](accessibility.md)). |
| **Content design** | Microcopy, voice, tone. |
| **Service design** | End-to-end experience across touchpoints. |

### The 2026 UX canon

- **Nielsen Norman Group (NN/g)** — the foundational research firm; usability heuristics; UX certifications.
- **Don Norman's UX principles** — visibility, feedback, constraints, mapping, consistency, affordance.
- **Jakob's Law** — users spend most of their time on other sites; they prefer your site to work the same way.
- **Fitts's Law** — time to acquire a target is a function of distance and size.
- **Hick's Law** — time to decide increases with the number and complexity of choices.
- **Material Design 3** — Google's design system; widely adopted (see [design-system.md](design-system.md)).
- **Human Interface Guidelines (HIG)** — Apple's design principles.
- **WCAG** — accessibility standard (see [accessibility.md](accessibility.md)).

### The UX process

1. **Research** — understand users, business, technical constraints.
2. **Define** — synthesize into personas, jobs-to-be-done, problem statements.
3. **Ideate** — sketch, brainstorm, explore possibilities.
4. **Prototype** — wireframes, mockups, interactive prototypes (in Figma).
5. **Test** — usability testing with real users; iterate.
6. **Ship & measure** — analytics, A/B tests, continuous research.

### UX artifacts

| Artifact | When |
|---------|------|
| **Persona** | Define target users. |
| **User journey / storyboard** | Map experience across touchpoints. |
| **Empathy map** | Quick synthesis of user research. |
| **Jobs-to-be-done (JTBD)** | Frame features as jobs. |
| **Information architecture (sitemaps, card sorts)** | Structure content. |
| **User flow / task flow** | Map paths to complete a goal. |
| **Wireframe** | Low-fidelity structure. |
| **Mockup** | High-fidelity visual design. |
| **Prototype** | Interactive simulation. |
| **Usability test script + report** | Run + document tests. |

Adoption: UX is now a default function in product teams. Every serious product has at least one UX designer; many have entire UX research teams. NN/g research is industry canon.

## When To Use It

- **You're designing any product** — period.
- **You want to understand users** — research.
- **You want to validate before building** — prototypes + usability tests.
- **You're redesigning** — research-driven iteration.
- **You want consistent UX across products** — design system (see [design-system.md](design-system.md)).
- **You want inclusive products** — accessibility (see [accessibility.md](accessibility.md)).

## When NOT To Use It

- **You're shipping a prototype for a hackathon** — skip; just code.
- **The user is yourself** — you know the domain; skip user research.
- **You have no users yet** — research the market, not specific users.
- **Purely internal tooling** — function > polish.
- **You're in pure execution mode** — designers can come later.

## Why It Matters in 2026

Three forces:

1. **AI-assisted UX workflows.** Figma AI, Galileo AI, UX Pilot, Magician — AI now generates wireframes, mockups, and copy from prompts. Designers move faster; the human role shifts to curation + judgment.
2. **Accessibility is now legal.** EU Accessibility Act (2025), ADA lawsuits in the US — accessibility is non-optional.
3. **Design systems became the default.** Every product team maintains a design system; consistency is expected.

Practitioner playbook in 2026:
1. **Research first** — don't ship without understanding users.
2. **Prototype cheap, test often** — Figma + usability tests.
3. **Build a design system** — see [design-system.md](design-system.md).
4. **Make it accessible** — see [accessibility.md](accessibility.md).
5. **Measure outcomes** — analytics + qualitative research.

## Comparison With Alternatives

| Alternative | Better when | Worse when |
|-------------|-------------|------------|
| **No UX (just ship)** | Hackathon; throwaway. | Real product. |
| **Visual design only** | Marketing pages. | Interactive products. |
| **Engineering-driven** | Internal tools. | Consumer products. |
| **AI-generated UX only** | Quick mockups. | Critical workflows. |
